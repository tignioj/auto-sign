## 前台本地网络准备与后台首运行防护（2026-10-15）

首次打开图形界面时，AutoSign 先在前台检查本地网络访问，再恢复设备读取和已开启的局域网服务；“自动续签”页显示检查状态、重试入口及系统设置入口。检查通过需要发现一次性发布的唯一 AutoSign Bonjour 服务，且结果来自 Wi-Fi 或有线网络接口；`NWBrowser.ready` 本身不作为授权成功的证据。拒绝、取消及无法确认访问时，不会新建后台任务。macOS 14 不进行本地网络隐私检查。

成功的前台检查记录绑定可执行文件内容、应用标识和安装位置，记录并不代替系统权限。后台入口在任何设备或网络操作前核对记录，缺少当前版本记录时停止并提醒先打开 AutoSign；更新或移动应用后需重新在前台检查。前台检查通过后，已有旧任务自动迁移为当前可执行文件路径，并添加 `AssociatedBundleIdentifiers` 关联 AutoSign。实现依据为 [Apple TN3179](https://developer.apple.com/documentation/technotes/tn3179-understanding-local-network-privacy) 的 macOS、授权触发和授权检查说明。

北京时间 23:16–23:18，使用实际打包应用完成验证：先由临时 launchd 任务启动没有前台检查记录的新构建，任务正常退出，记录“此版本尚未在前台完成本地网络检查”，未调用设备续签协调器。随后打开图形界面，实际 Bonjour 检查通过并生成匹配当前可执行文件的记录；旧后台任务自动补齐应用关联和路径，并立即完成对两台设备四个应用的常规检查，四个应用均未到续签窗口。临时测试任务已卸载。

本机系统沿用了 AutoSign 的已有本地网络许可，因此这次没有重置系统隐私设置或重现首次系统弹窗；允许、拒绝、无法确认、并发检查、取消及更新/移动后旧记录失效由自动化测试覆盖。120 项常规测试通过，Release 构建和代码签名验证通过。默认 ad hoc 签名仍可能在更新后重新请求系统授权；构建脚本支持 `AUTOSIGN_MAC_SIGNING_IDENTITY` 指定稳定的 Apple 签名身份，未指定时保留原构建方式。

本地证据位于 `dist/DeviceTests/local-network-setup/guard-result.json`、`foreground-result.json`，目录内还保留构建日志、源文件校验清单及旧版备份位置。该目录被 Git 忽略，未随仓库发布。

## 复现步骤

重复真机验证需要 Xcode 账号有效、目标设备已配对、保持解锁，且应用已在 Store 应用库中。在项目根目录运行以下命令，会实际向 Apple 请求新文件并更新该设备的受管理应用，另行重新启动应用以验证签名：

```sh
swift build
AUTOSIGN_INTEGRATION_REFRESH_DEVICE='替换为设备UDID' \
AUTOSIGN_INTEGRATION_REFRESH_REPORT="$PWD/dist/DeviceTests/verification-profile-only.json" \
swift test --filter integrationProfileOnlyRefreshWhenConfigured
```

可以用 `AUTOSIGN_INTEGRATION_REFRESH_APPS` 指定逗号分隔的应用记录 ID（不是 Bundle ID）；未指定时处理该设备应用库中的全部应用，Store 自身最后处理。此测试要求最终走 `profileOnly` 路径，并显式启用启动验证、另行终止和重启应用，不受界面启动验证开关控制。
