# AutoSign

AutoSign 是一个原生 macOS 图形工具，用自己的 Apple 开发者身份，为应用源中的 `.ipa` 重新签名并安装到自己的 iPhone 或 iPad。支持跨源批量安装、按设备和应用自动续签，以及通过 [AutoSign Store](https://github.com/tignioj/auto-sign-store) 手机客户端安装、更新和刷新签名。

当前源码版本为 **1.5.0（build 8）**。安装和续签由 Mac 完成，手机端无需输入 Apple ID 或保存签名证书。

## 使用前准备

1. 安装支持 Swift 6 的完整 Xcode，完成首次启动所需的组件安装，在 **Xcode → Settings → Accounts** 登录 Apple ID。
   首次打开 AutoSign 时，在前台允许本地网络访问并等待“检查通过”；拒绝后可在 **系统设置 → 隐私与安全性 → 本地网络** 中允许 AutoSign，再点击“检查本地网络权限”。此项用于无线安装、手机 Store 连接与后台续签，macOS 14 无此权限要求。
2. 用 USB 连接所有目标设备、解锁并选择“信任此电脑”。
3. 如果设备尚未完成开发者配对，在 AutoSign 中逐台点击 **发起配对**，保持设备解锁并确认提示。
4. 在每台设备的 **设置 → 隐私与安全性 → 开发者模式** 中开启开发者模式并重启。
5. 在 AutoSign 的“签名设置”确认签名团队和描述文件。AutoSign 会尝试读取钥匙串证书及 Xcode 本地未过期、匹配所选设备的描述文件；也可点击 **选择…** 手动指定该团队的 `.mobileprovision`。

首次安装使用所选描述文件确定签名团队，再由 Xcode 为每个应用和目标设备申请独立的新描述文件，无需事先为源中的每款应用手动下载文件。优先使用自己的开发描述文件；免费 Personal Team 可用，签名通常有效 7 天。后续续签或升级沿用各应用已保存的标识和团队。

如果本机还没有开发描述文件，可先在 Xcode 创建一个 iOS App 工程，选择自己的 Team、唯一 Bundle ID 和自动签名，以已连接的真机为目标构建，再回到 AutoSign 点击 **刷新账号与证书**。需要手动选择时，可在 Finder 的“前往文件夹”中检查以下 Xcode 缓存目录：

```text
~/Library/Developer/Xcode/UserData/Provisioning Profiles/
~/Library/MobileDevice/Provisioning Profiles/
```

首次安装完成后，还需要在每台 iPhone 或 iPad 上进入 **设置 → 通用 → VPN 与设备管理**，在“开发者 App”下选择本次签名使用的开发者并点 **信任**，然后再打开应用。每台设备通常只需操作一次；更换签名身份后可能需要重新信任。

> 开启“开发者模式”只表示设备允许运行开发 App，不会自动把设备 UDID 写入描述文件。如果当前描述文件缺少目标设备，AutoSign 会通过 Xcode 尝试注册设备并重新生成描述文件。

## 构建和运行

要求 macOS 14 或更高版本，并安装支持 Swift 6 的完整 Xcode；下载发行版后，签名和设备操作仍依赖 Xcode。手机 Store 要求 iOS / iPadOS 17 或更高版本。

### 下载发行版

从 [GitHub Releases](https://github.com/tignioj/auto-sign/releases) 下载与 Mac 芯片匹配的压缩包，解压后打开 `AutoSign.app`：

| Mac | 下载文件 |
| --- | --- |
| Apple 芯片 | `AutoSign-v版本号-macOS-arm64.zip` |
| Intel | `AutoSign-v版本号-macOS-x86_64.zip` |

每个压缩包附带 `.sha256` 校验文件。建议将应用放到固定位置后再开启后台自动续签。

### 从源码构建

在项目根目录运行：

```sh
./Scripts/build-app.sh
open dist/AutoSign.app
```

开发调试可执行：

```sh
swift build
swift run AutoSign
```

`swift build` 会同时生成管理设备描述文件的 `AutoSignDeviceHelper` 和 `AutoSignRemoteHelper`。打包脚本将这两个原生组件和 `ProvisioningHelper` Xcode 工程放入应用，并进行本地 ad hoc 签名；无需额外安装 Python 或 libimobiledevice。后台续签建议使用打包后的应用，避免构建目录变化导致任务找不到可执行文件。

## 操作

界面按功能分为独立页面，通过左侧导航切换：

| 页面 | 内容 |
| --- | --- |
| 安装应用 | 选择目标设备、浏览源中的应用、多选安装或续签、查看本次处理结果 |
| 应用源 | 添加、刷新、移除订阅，跳转浏览源中的应用 |
| 设备管理 | 按 iPhone / iPad 浏览设备、选择设备、USB 配对与开发者模式提示 |
| 自动续签 | 后台任务和启动验证开关、各设备应用的到期时间与续签记录 |
| 手机连接 | AutoSign Store 局域网服务、连接地址、配对密钥及源更新检查 |
| 签名设置 | Xcode 账号状态、签名证书、描述文件 |
| 使用指南 | 首次使用、无线连接、开发者信任及设备注册说明 |

切换页面保留本次应用选择、搜索条件及操作进度。左下角始终显示操作状态，点击可返回安装页；安装页提供设备和签名设置的快捷入口。

连接设备后，AutoSign 会恢复上次选择的一台设备，首次使用时优先选择第一台可用设备，并读取钥匙串证书和 Xcode 中可用的描述文件。设备卡片只支持单选，可按 iPhone 或 iPad 分类浏览，也可直接在安装页切换设备。先选择一台设备，再从所有已添加源的完整应用列表中勾选一个或多个应用；同一 Bundle ID 每批只处理一次。切换目标设备会清空本次应用选择，设备离线时不会自动改装到其他设备。

点击 **安装所选应用**，会逐个重新检查最新源、下载并验证 IPA，为每个应用生成独立的描述文件后签名安装。点击 **续签所选应用**，则使用这台设备已有安装记录中的原始 IPA、应用标识及团队，只刷新签名，不自动升级；所选应用必须都已在该设备安装。每个应用分别显示进度、结果、到期时间或错误，某个应用失败后继续处理其余应用。处理期间锁定设备及应用选择，并暂停源更新。

### 续签校验与兼容

Personal Team 免费签名通常只有 7 天有效期。手机 Store 手动刷新或 Mac 进入后台续签窗口时，AutoSign 会备份并隔离匹配该团队与 Bundle ID 的 Xcode 缓存，使用独立构建目录请求 Apple 重新签发描述文件。免费签名必须通过新 UUID、签发日期、新的 7 天有效期及到期时间延长校验，旧文件或有效期不足时直接报错，不会把普通重装显示为续签成功。缓存处理失败时回滚，中断后下次续签会自动恢复；不会撤销开发者证书。如果 Xcode 暂时无法挂载开发者磁盘镜像或等待目标设备准备超时，手动及后台续签都会等待 15 秒后自动重试一次；再次失败时保留错误详情。系统更新后可先通过 Wi-Fi 重试，持续失败再解锁设备并通过 USB 连接，在 Xcode 中检查设备支持。

Mac 1.4.1 起，续签优先通过 macOS 的 MobileDevice / `com.apple.misagent` 服务单独安装新描述文件，不重新签名或传输 IPA。只有已安装证书被新描述文件允许、原签名权限兼容且不包含未单独处理的扩展时才使用此路径。随后读回设备上的原始 CMS 文件，确认与已校验的新文件逐字节一致，检查安装位置和版本保持不变。

Mac 1.6.0 起，如果 MobileDevice 无法发现已配对的无线设备，会再尝试 Xcode 已建立的 CoreDevice 隧道及 `com.apple.misagent.shim.remote` 服务。连接前核对目标 UDID、配对和开发者模式，服务握手后再次核对设备身份，再执行相同的描述文件安装与逐字节读回验证。Finder 的无线同步连接与 Xcode 的开发者连接可能分别可用；Finder 暂时找不到设备不等于不能单独更新描述文件。CoreDevice 通道中断时重新发现端口并有限重试，不会将连接错误直接当成需要重装。

安装页可按设备开启 **此设备仅更新描述文件，禁止覆盖安装**，默认关闭。该限制保存到本机，并用于此设备的 Mac 手动、手机 Store 和后台续签；连接或兼容性检查失败时停止，不会回退重装。首次安装和主动点击“安装所选应用”仍按正常安装流程执行。

“自动续签”页面提供 **刷新签名后验证应用启动** 开关，默认关闭并保存到本机。Mac 安装页的手动续签、手机 Store 发起的单个 / 批量刷新及 Mac 后台续签都遵循此设置，包括续签时的覆盖安装。关闭后不会自动启动应用或检查进程，仍校验新描述文件、有效期及安装结果，完成提示为“已跳过启动验证”。开启后会启动应用并检查进程仍在运行，不会主动结束已有应用或切换到前台；手机锁定时启动验证会失败，等待解锁后重试。关闭启动验证不保证锁定设备可完成其他设备操作。

证书变化、权限不兼容、应用扩展或设备明确不支持单独更新时，自动回退到原标识、原团队的完整签名和覆盖安装，并按上述开关决定是否验证启动。扩展仍受现有签名器的支持范围限制，不支持的扩展会报错。若系统不支持读回描述文件，此路径依据已验证的新签名包、安装成功响应及可选的启动检查确认结果；支持读回时必须核对设备文件。临时 Wi-Fi Mux 连接错误及应用信息查询中的 RSD 分配失败、连接建立后断开，最多重连两次，每次等待 2 秒并重新探测原目标设备；旧描述文件通道仍失败时再尝试核对过设备身份的 CoreDevice 通道，端点发现也会有限重试。连接中断、设备锁定、取消、本地校验失败、设备报告描述文件被封禁或无法完成验证，都不会盲目触发重装。版本升级及首次安装继续使用完整安装流程，不要求其到期时间晚于原签名。本功能不引入 AltStore 的 Apple ID / Anisette 登录链路；MobileDevice 是系统设备协议实现，仍需随系统版本验证兼容性。

若 Apple 要求重新登录或接受新的开发者协议，需要先在 Xcode 中完成该步骤。

当描述文件不包含所选设备时：

- 免费 Apple ID / Personal Team：保持 Xcode 账号登录、Mac 联网，并确保设备已解锁、信任此 Mac。AutoSign 会请 Xcode 自动注册设备。
- 付费开发者账号：如果自动注册失败，可在 Apple Developer 的 **Certificates, Identifiers & Profiles → Devices** 中添加 UDID，再重新生成并下载 Development 或 Ad Hoc 描述文件。

## 从应用源安装

打开侧边栏的“应用源”，粘贴 AltStore / SideStore 格式的 JSON 源地址并点击 **添加源**。安装页没有源时，也可点击 **添加应用源** 跳转到此页面。也可以点击 **添加 Kazumi 源** 使用以下地址：

```text
https://raw.githubusercontent.com/ChouChiu/Kazumi-AltStore-Source/kazumi/generated/apps.json
```

安装手机续签客户端时，点击 **添加 AutoSign Store 源**，或手动添加以下固定地址：

```text
https://raw.githubusercontent.com/tignioj/auto-sign-store/source/apps.json
```

该源由 [auto-sign-store 的 GitHub Actions](https://github.com/tignioj/auto-sign-store/actions) 在正式版本标签发布后自动更新；IPA 托管在 GitHub Releases，无需本地构建 Store。

“安装应用”页按源直接展开所有已订阅的应用，无需切换下拉框。可以跨源搜索应用名称或 Bundle ID，查看最新版本、包大小、iOS 版本要求和更新说明，同时显示当前设备的受管理安装版本与签名到期时间。勾选多个应用，或点击 **全选当前列表** 选择搜索结果中的应用；同一 Bundle ID 只选择一次，搜索后已选应用会保留在本次操作列表中。确认目标设备和签名设置后，点击 **安装所选应用**。已安装应用可使用同一份选择点击 **续签所选应用**。

源地址和上次获取的列表会保存在本机；打开界面或点击 **刷新源** 可检查更新。最新版本遵循 [AltStore 的版本顺序规则](https://faq.altstore.io/developers/updating-apps)，使用 `versions` 数组的第一项，也兼容旧源的顶层 `version` / `downloadURL` 字段。当前不会按设备系统版本自动改选历史版本，安装前请核对列表显示的系统要求。刷新失败时保留上次列表，下载前必须成功重新获取源。

安装时的临时 IPA 下载到 `~/Library/Application Support/AutoSign/Downloads/`，处理后清理；成功安装的原始 IPA 和描述文件会按设备、应用独立保存在应用库中，供手动与后台续签使用。切换设备或应用选择不影响其他应用的续签。手机端的版本升级见下方“源更新检测与一键更新”。移除源仅移除订阅记录，已保存的应用续签资产会保留。

参考：[Kazumi iOS 安装说明](https://kazumi.app/docs/misc/how-to-install-in-ios/) · [AltStore 源格式](https://faq.altstore.io/developers/make-a-source)。

## 源更新检测与一键更新

Mac 1.4.0 配合 Store 1.2.0，开启局域网服务后默认每 30 分钟检查所有已订阅源；服务启动时若已到检查时间会立即补查，签名、下载或刷新忙碌时延后重试。Mac 需保持 AutoSign 运行并联网，休眠期间暂停，唤醒后补查。可以在“手机连接”页关闭自动检查；检查时间与缓存保存在本机，重启不会重新计时或丢失已发现的更新。

手机“我的应用”显示可更新数量徽标、当前与最新版本、版本说明，可单独更新或点击 **一键更新全部**（每批最多 50 个）。手机在前台每 30 秒同步，重新打开也会自动同步；**检查更新**可立即让 Mac 获取所有远端源。提示在 Store 内显示，手机完全关闭时没有系统推送。离线时显示上次结果，源检查失败会显示提示并保留缓存。

Mac 1.7.0 起，“安装应用”侧栏显示当前设备的更新数量，应用列表标记 **可更新** 并显示当前版本 → 最新版本；勾选后点击 **安装所选应用** 即可升级。GitHub raw 源地址的短分支写法与 `refs/heads/分支` 写法可匹配同一条旧安装记录，无需重新安装来恢复更新提示。

手机更新只针对所选设备已有的受管理应用，取源的 `versions` 第一项，与 AutoSign 应用库记录的安装版本及构建号比较，避免降级和重复提示。旧安装记录可从保存的原始 IPA 识别应用及构建号；已有源关联会固定使用该源，没有关联且多个源都包含相同应用时不自动选择。移除订阅后不再提示该源的版本。通过其他工具更改设备上的应用版本，不会自动同步到此应用库。

更新任务在执行前保存，逐应用重新获取源、下载并验证 IPA 的 Bundle ID、版本、构建号及完整性，再沿用原应用标识和签名团队覆盖安装。失败的应用保留旧记录，其他应用继续执行；Store 自身最后更新，手机退出或被覆盖安装后 Mac 继续执行，重开可恢复结果。相同请求不会重复执行。“刷新签名”仍使用已保存的 IPA，不自动升级。

## 同一 Wi-Fi 后台自动续签

在“自动续签”页打开“为已安装的应用自动续签”。AutoSign 会安装当前用户级后台任务，加载时立即检查，之后每 30 分钟检查一次。在 **Mac“安装应用”页**成功安装或续签过应用的设备会加入后台目标列表，切换界面当前设备不会移除此前的目标，旧版保存的设备组也会保留。仅通过手机 Store 操作新设备不会自动将其加入后台目标，需先在 Mac 为该设备成功安装或续签一次，并在“自动续签”确认它已列出。

后台从应用库读取这些目标设备的全部应用记录，按每个应用各自的到期时间判断：剩余超过 24 小时则跳过，进入最后 24 小时或已经过期则尝试续签。同一应用在不同设备上也独立判断；不依赖界面当前选择的设备、应用、描述文件或证书，不会自动安装到没有该应用记录的设备。

续签复用该应用记录自己的原始 IPA、描述文件、团队及证书，Apple 发放并通过校验的新描述文件后，优先单独更新设备描述文件，不兼容时覆盖安装；仅在开启“刷新签名后验证应用启动”时自动启动应用验证。AutoSign Store 自身最后处理。某个应用失败或某台设备离线不会阻止其他应用处理；只有确认成功后才更新该应用的到期记录，失败或离线的应用在后续检查中继续重试。已有应用库记录自动纳入，无需重新安装；没有记录的旧应用需要通过 AutoSign 安装一次。此功能只刷新签名，不自动升级应用版本。

“签名设置”页显示 Xcode 本地账号记录；“自动续签”页每 15 秒刷新，显示后台任务加载状态、预计下次检查时间，以及每台后台目标设备的汇总状态和各应用的独立到期时间、续签窗口、预计下次续签时间、最近成功时间与失败详情。设备最早到期时间取该设备应用记录的最小值。检测到账号记录不等于在线登录仍有效；最近旧版后台错误仍可展开查看。续签时间为预计值，Mac 休眠、设备离线或 Apple 尚未发放新描述文件都会延后。

Mac 需要保持开机、当前用户登录且联网，无线目标设备与 Mac 必须位于同一可互访的局域网。每台设备首次无线使用前仍需通过 USB 完成配对，并在 Finder 中启用“连接到 Wi-Fi 时显示此设备”；也可保持 USB 连接。

灭屏、锁屏和系统睡眠是不同状态。插电时开启“使用电源适配器供电且显示器关闭时，防止自动进入睡眠”允许系统在灭屏后继续运行，但不保证锁屏后 Xcode 的账号凭据仍可读取。本机 Xcode 27 的锁屏测试中，凭据读取返回 `errSecInteractionNotAllowed (-25308)`，随后 Xcode 移除了本地账号记录。AutoSign 在请求新描述文件前检查当前登录会话：锁屏时显示“等待 Mac 解锁”，解锁后自动继续；无法确认会话状态时停止调用 Xcode。此检查不绕过锁屏，也不保证锁屏期间即时续签。若此前已出现 `missing Xcode-Username`、`missing Xcode-Token` 或 `No Accounts`，需先解锁 Mac 并在 **Xcode → Settings → Apple Accounts** 重新登录。Mac 在检查通过后再次锁屏仍可能导致凭据读取失败。

后台续签由 launchd 单独启动，关闭 AutoSign 图形界面后仍可执行，无需开启“手机连接”的局域网服务。手机请求和源更新检查则要求 AutoSign 图形应用保持运行。Mac 休眠时任务可能延后，不保证在预计时间执行。移动或重新安装 AutoSign 后，应在新位置关闭再开启自动续签，以更新后台任务的可执行文件路径。

Mac 1.8.0 起，开启后台任务前，AutoSign 会在前台检查本地网络访问。检查未完成或无法确认访问时不会新建后台任务。后台进程还会核对当前可执行文件和位置是否完成过前台检查；更新或移动应用后，请先打开 AutoSign 完成检查。缺少当前版本的检查记录时，后台在访问局域网前停止并提示完成首次设置。已有后台任务会在前台检查通过后自动补上应用关联和当前路径，避免权限首次请求留到无人值守时。

macOS 没有通用的本地网络授权查询 API；这里通过短暂发布和浏览唯一的 AutoSign Bonjour 服务验证当前访问，浏览器启动成功本身不算通过。检查记录也不代替系统权限，用户之后撤销权限或网络不可用时仍可能失败。系统按代码签名识别应用，默认临时签名的构建在更新后可能重新请求授权。正式发行应使用稳定的 Apple 签名身份；本地构建可通过 `AUTOSIGN_MAC_SIGNING_IDENTITY` 指定 Mac 代码签名身份，未指定时仍使用 ad hoc 签名。参见 [Apple 本地网络隐私说明](https://developer.apple.com/documentation/technotes/tn3179-understanding-local-network-privacy)。

## AutoSign Store 手机客户端

[auto-sign-store](https://github.com/tignioj/auto-sign-store) 提供 iOS 17+ 原生客户端，可在手机管理应用源、选择应用让 Mac 自动下载安装，查看签名到期时间、逐个 / 批量刷新应用，并刷新 Store 自身。在“应用源”页添加 AutoSign Store 源，再到“安装应用”页勾选 Store 并点击 **安装所选应用**；也可以用相邻项目的 `Scripts/build-ipa.sh` 在本地构建。

在本工具的“手机连接”页开启局域网服务。手机与 Mac 连接同一可信 Wi-Fi，允许本地网络权限，在 Store 中发现 Mac 并输入页面中的配对密钥，核对并选择本机设备后即可发起刷新。发现失败时可手动输入 Mac 显示的 `.local` 地址，或 `http://Mac的局域网IP:8091`。服务监听端口 `8091`，通过 Bonjour `_autosign._tcp` 广播；AutoSign 图形应用必须保持运行，首次无线连接前仍需 USB 配对。重置配对密钥后，手机需使用新密钥连接。

各功能的最低版本如下，建议两端均使用最新版：

| 功能 | Mac AutoSign | AutoSign Store |
| --- | --- | --- |
| 手机源管理与安装 | 1.3.0 | 1.1.0 |
| 源更新检测与一键更新 | 1.4.0 | 1.2.0 |
| 优先仅更新描述文件续签 | 1.4.1 | 兼容旧客户端，界面说明需 1.2.0 |

手机“应用源”与 Mac 共用源订阅，可添加、刷新、移除源，浏览和搜索应用，选择目标设备并发起安装。Mac 先保存任务，再重新检查最新源、下载并验证 IPA、向 Xcode 请求匹配的描述文件，然后签名和安装。进度及错误在手机“活动”中显示；手机退出后 Mac 继续执行，重新打开可恢复结果。

Mac 保留最近 30 条手机任务；在记录保留期间，相同请求编号和参数返回原任务，不会重复安装。Mac 服务重启后，已完成结果保留，未完成项会标记为中断，需要重新发起，不会自动接着安装。

首次安装采用 Mac 当前描述文件的签名团队，为应用生成独立的团队专属 Bundle ID；不会复用 Store 的明确标识覆盖 Store。升级受管理应用保留原标识和团队，后续刷新继续使用已安装版本的原始 IPA。手机不需要输入 Apple ID 或持有证书。两端均需更新；本地构建不更新公开源或 GitHub Release。

成功安装后，原始 IPA 和每应用独立描述文件会保存在 `~/Library/Application Support/AutoSign/Store/`，供手动、手机和后台续签共用。没有应用库记录的旧应用需通过 AutoSign 安装一次才能纳入列表；已在应用库中的旧记录兼容迁移，无需专门重装。Store 自身最后处理，优先仅更新描述文件；发生覆盖安装导致手机应用关闭时，Mac 继续执行。有效期延长并通过设备验证后才显示刷新完成，启动检查遵循 Mac 中的开关。

实现参考：AltStore 的 [`FetchProvisioningProfilesOperation`](https://github.com/altstoreio/AltStore/blob/main/AltStore/Operations/FetchProvisioningProfilesOperation.swift) 每次刷新获取新描述文件；[Apple 的自动签名说明](https://developer.apple.com/help/account/provisioning-profiles/edit-download-or-delete-profiles/) 明确指出本地缓存满足条件时 Xcode 不会请求新描述文件。AutoSign 继续使用 Xcode 已登录的账号完成请求，手机无需输入 Apple ID。

局域网服务默认关闭，所有接口需要配对密钥；此版本使用 HTTP，只在可信局域网使用，不要将端口映射到公网。完整构建、首次安装和自身刷新见 [AutoSign Store README](https://github.com/tignioj/auto-sign-store#readme)，接口定义见 [API v1 说明](https://github.com/tignioj/auto-sign-store#局域网-api-v1)。

## 本机数据与排错

运行数据位于 `~/Library/Application Support/AutoSign/`：

| 相对该目录的路径 | 用途 |
| --- | --- |
| `Store/library.json`、`Store/Packages/` | 按设备和应用保存的安装记录、原始 IPA 及描述文件，后续续签依赖这些资产 |
| `Store/jobs.json` | 手机任务历史与逐应用结果 |
| `Downloads/` | 源安装的临时下载目录，处理结束后清理 |
| `Profiles/` | Xcode 为应用生成的新描述文件 |
| `ProfileCacheBackups/` | 描述文件缓存隔离与中断恢复资料 |
| `Logs/refresh.log`、`Logs/refresh-error.log` | 后台任务的标准输出与错误日志 |

源订阅、缓存、设备选择和开关等配置保存在本机用户偏好中。后台任务文件为 `~/Library/LaunchAgents/local.autosign.desktop.refresh.plist`；关闭自动续签会卸载该任务，保留应用库。移除源不卸载应用，也不删除其续签资产。

| 问题 | 检查方式 |
| --- | --- |
| 找不到设备或显示未就绪 | 解锁设备并通过 USB 信任、配对，确认开发者模式；无线连接需启用 Finder 的 Wi-Fi 显示选项并使用可互访的网络 |
| `xcrun` 找不到 `devicectl` 或无法调用 `xcodebuild` | 确认安装完整 Xcode，执行 `xcode-select -p` 检查当前工具路径；只有 Command Line Tools 不够 |
| 无证书、描述文件或 Apple 拒绝签发 | 在 Xcode 检查账号、Team、证书和开发者协议；按“使用前准备”生成初始开发描述文件，保留完整错误详情 |
| 提示无法挂载开发者磁盘镜像或准备设备超时 | AutoSign 会等待 15 秒重试一次；持续失败时解锁并通过 USB 连接，在 Xcode 检查设备支持 |
| 手机找不到 Mac 或密钥错误 | 确认局域网服务开启、AutoSign 正在运行、本地网络权限及防火墙设置；尝试手动地址，密钥重置后重新配对 |
| 后台未续签 | 在“自动续签”确认任务已加载、设备已列为目标及应用进入 24 小时窗口，展开失败详情；移动应用后关闭再开启后台任务 |
| 应用已过期，Store 无法打开 | 在 Mac“安装应用”选择原设备和已有记录的应用，点击“续签所选应用”；按系统提示重新信任开发者 |

> iOS 应用安装包的扩展名是 `.ipa`，不是 `.ipk`。工具不绕过激活锁、开发者模式、证书校验或 iOS 代码签名安全机制。请只签名和安装你有权使用、测试或分发的应用。IPA、描述文件和证书属于本机私有资产，已默认被 Git 忽略。

## 开发与验证

在项目根目录运行常规自动测试：

```sh
swift test
```

测试覆盖设备选择、跨源批量处理、逐应用后台续签、源缓存与 IPA 校验、版本更新、请求鉴权与去重、描述文件有效期、兼容性回退、Wi-Fi 有限重连、取消及旧记录迁移。未设置集成测试环境变量时，真机测试函数直接返回；常规测试不向 Apple 请求签名，也不安装或续签真机应用。

`AUTOSIGN_INTEGRATION_IPA` 与 `AUTOSIGN_INTEGRATION_PROFILE` 同时设置会启用真实签名安装；`AUTOSIGN_INTEGRATION_REFRESH_DEVICE` 启用描述文件真机续签测试；`AUTOSIGN_SOURCE_INTEGRATION_URL` 启用真实源下载。日常测试前应确认未继承这些变量。

仅更新描述文件续签已完成真机验证；手机“更新 / 一键更新全部”尚未完成真机版本升级验证。详细记录及复现步骤见 [描述文件续签真机验证](docs/profile-refresh-verification.md)。

发行工作流见 [`.github/workflows/release.yml`](.github/workflows/release.yml)：推送 `v*` 标签后，先检查标签提交属于 `main` 历史，再分别测试、构建 Apple 芯片与 Intel 应用，生成 ZIP 和 SHA-256 文件并发布到 GitHub Releases。普通分支推送不会触发该工作流。版本号和构建号定义在 [`Resources/AppInfo.plist`](Resources/AppInfo.plist)。
